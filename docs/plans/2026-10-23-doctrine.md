# Doctrine Implementation Plan

> **For agentic workers:** implement task by task in order; steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local repo of skills - a language-neutral core (`doctrine`, `architecture`, `health`) plus React, games, Python and Node packs - linked into every Claude session, which agents apply while building and reviewer agents check against.

**Architecture:** Each skill is a folder under `skills/` with a `SKILL.md`. `install.mjs` links them into `~/.claude/skills` and `~/.agents/skills` with directory junctions, backing up any real folder it replaces. The one runnable piece is `skills/health/scripts/health.mjs`, a runner that hooks free OSS tools into any project, shaped like `react-health`'s. No custom checker and no test suite.

**Tech Stack:** Markdown skills; Node 25 ESM scripts; ESLint 10.10.0, typescript-eslint 8.70.0, eslint-plugin-sonarjs 4.2.1, eslint-plugin-import-x (current), knip 6.36.0, jscpd (current), TypeScript 6.0.3 in the health skill's own `node_modules`; ruff 0.17.2 and vulture through `uvx`; pyright 1.1.414; gitleaks, OSV-Scanner and Semgrep CE as machine installs.

**Spec:** `docs/specs/2026-10-23-doctrine-design.md` (approved 23 Oct 2026, revised: skills only, the folder model, a general health skill).

## Global Constraints

- Repo: `C:\Users\brand\Desktop\Projects\doctrine`, branch `main`, local only - never pushed.
- Limits stated in the skills: **400** code lines per hand-written source file, **600** per test file, **200** per React component with no waiver, **800** hard ceiling for a waived file. A code line is neither blank nor comment-only.
- Waiver: `doctrine-allow size: <D1|D2|D3|E> - <reason>` at the top of the file; E names its benchmark.
- Folder model: purpose folders, then units that grow from a file into a same-named folder with one entry; split-out code is private to its unit or goes to a subject unit in `utils/`. No `misc`/`helpers`/`common`; no single-file folders; units at most two levels below their purpose folder.
- Health gates only: type errors (where the project has a config), import cycles, committed secrets. Everything else is read. A missing tool prints its install command and is not a failure.
- No tool is ever added to a checked project; tools live on the machine or in `skills/health/scripts/node_modules`.
- Every `SKILL.md` frontmatter `name` matches its folder; skills carry no pointers to files outside themselves.
- Uninstall unlinks only; no recursive delete ever runs on an installed skill path.

## Review Focus

1. **A skill that fails to load** - malformed frontmatter or a `name` that differs from its folder silently drops it. Checked wherever a `SKILL.md` is written.
2. **Health on a machine missing tools** - every absent tool is listed with its install command and the run still ends with a summary and a sensible exit code. Checked in Task 4.
3. **Health on a mixed project** - Junk Rally is TS with a Python `tools/` folder; both stacks' checks run. Checked in Task 4.
4. **Re-running the installer** - a second run changes nothing; a real folder is backed up before it is replaced. Checked in Tasks 1 and 6.
5. **The React rename seam** - CLAUDE.md and project copies that name `react-doctrine` and friends still resolve after install. Checked in Task 6.

### Task 4: The `health` skill

**Files:**
- Create `skills/health/SKILL.md`, `skills/health/scripts/package.json`, `health.mjs`, `tools.mjs`, `stacks.mjs`, `sizes.mjs`, `pycycles.py`, `eslint.config.mjs`, `ruff.toml`

**Interfaces:**
- `stacks.mjs`: `detectStacks(root: string): { ts: string[], python: string[] }` - folders (depth 3, skipping `node_modules dist build .venv venv __pycache__ .git`) holding a `package.json` with `typescript` or a `tsconfig.json`, and folders holding `pyproject.toml`, `requirements.txt` or `setup.py`.
- `tools.mjs`: `TOOLS: { name: string, stacks: ('ts'|'python'|'any')[], gate: 'always'|'config'|false, available(): boolean, install: string, args(dir: string): { cmd: string, args: string[] } }[]` - one entry per spec section 5 row. `gate: 'config'` gates only when the project has the tool's config (`tsconfig.json`, `pyrightconfig.json` or `[tool.pyright]`).
- `sizes.mjs`: `oversized(root: string): { rel: string, lines: number, limit: number }[]` - code-line counts with the limits and exemptions from the spec (generated header, `*.min.js`, data-only, waiver line).
- `pycycles.py`: prints each Python import cycle found under the given folder (absolute and relative imports between the project's own modules), exit 1 if any.
- `health.mjs`: `node health.mjs [dir=.]` - detects stacks, runs each available tool, prints `=== <tool>` sections and a `PASS|FAIL|READ|SKIP  <tool>` summary (SKIP lists the install command), exit 1 if a gate failed, else 0.
